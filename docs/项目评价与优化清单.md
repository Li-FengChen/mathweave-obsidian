# 项目评价与优化清单

评价日期：2026-10-13

> 本报告保留升级前的问题证据；20 项对应优化已在 2.1 实现。每项当前处理和验证范围见 [2.1 优化完成情况](2.1优化完成情况.md)。以下总体评价、源码位置和复现描述均针对历史基线。质量评估框架已建立，小样例不能证明一般数学准确率。

## 总体评价

项目已经形成“导入对话 → 本地或 AI 提取 → 笔记预览 → 保存到 Obsidian”的基本流程。解析、提取、AI 接口、笔记写入和界面分开，规模适中，适合继续迭代。系统密钥链、后台分析、自动备份、GUI 与命令行两个入口，都是已有的良好基础。

当前更适合定位为功能原型。阻碍日常可靠使用的主要问题是内容完整性、概念识别、增量更新和输入解析。建议先修复这些问题，再投入界面美化和更多导入渠道。

本次检查覆盖全部 Python 源码、依赖清单和 Markdown 使用说明。所有 Python 源文件通过语法编译检查；用临时样例验证了核心解析、提取、合并、索引和预览转换行为。没有连接真实 AI 服务，没有操作实际 Obsidian 仓库，也未启动 GUI：当前可用运行环境没有安装 PyQt6、openai 和 keyring。因此，本报告不声称已经验证 GUI 运行稳定性、服务商兼容性或数学提取准确率。

## 优先级说明

- **P0：优先修复。** 已存在内容丢失、误合并或错误解析，影响核心使用。
- **P1：下一轮完善。** 提高保存可靠性、笔记有效性和操作体验。
- **P2：后续建设。** 提高可维护性、可验证性和分发体验。

“已复现”表示用本地样例观察到了该行为；“代码确认”表示当前实现直接体现该问题；“增强建议”表示待新增能力，不代表已经发生故障。

## P0：内容完整性与核心流程

### 1. [x] 取消以新笔记长度决定覆盖旧笔记

- **状态：已复现。** 新内容长度超过旧内容的 1.15 倍就直接替换，旧笔记中的人工补充和适用条件可能丢失。
- **优化：** 将人工内容与自动内容的更新规则明确化；提供更新差异预览和冲突处理，避免把“更长”当作“完整保留旧知识”的依据。
- **验收：** 旧笔记包含人工备注、新笔记明显更长时，备注仍保留；用户可以查看和恢复历史内容。

- **优化：** 只解析文件开头的 frontmatter；以段落、公式块、代码块等完整单元合并，保留重复但必要的结构符号。
- **验收：** 含正文分隔线、多组公式、重复列表行和代码块的更新后，内容完整且可正常渲染。

### 3. [x] 修复不同知识点被误合并

- **优化：** 使用明确的规范名称和别名规则；父子概念建立关联，合并存疑时保留独立笔记。拒绝空标题，避免仅凭子串包含判断相同。
- **验收：** 定积分与不定积分分别保存；同一概念的已知别名可以合并；合并结果不依赖输入顺序。
- **位置：** [core/extractor.py:139](../core/extractor.py#L139)

- **优化：** 保留导入后的结构化 Conversation，或保证显示格式与解析格式互相兼容；输入发生编辑时再重新解析，并明确来源变化。
- **验收：** 导入后进入分析，消息数量、角色、顺序和来源保持一致。

### 5. [x] 完善 JSON 对话解析与异常处理

- **优化：** 支持多会话选择或批量导入；按明确选定的分支恢复对话；校验节点、消息、时间字段，给出可理解的错误。文本编码错误应提示或允许选择编码，避免静默丢字符。
- **验收：** 多会话、重新生成的答案、缺失时间、异常节点、非 UTF-8 文本均能正确处理或清楚拒绝；解析失败后界面可以继续操作。
- **位置：** [core/parser.py:53](../core/parser.py#L53)、[ui/main_window.py:365](../ui/main_window.py#L365)

### 6. [x] 修复预览隐藏正文的问题

- **验收：** 写入失败不会把完整旧文件变成截断文件；每次有效更新有独立备份；失败后能明确识别已完成和未完成的笔记。

## 推荐实施顺序

1. 修复第 1–6 项，先保证输入和笔记内容完整。
2. 完成第 7–12 项与第 17 项，让保存、去重、属性和索引可靠。
3. 完成第 13–16 项，改善长对话、任务控制、数学预览和人工审核。

第一轮完成的标准应是：能够正确导入一段多轮对话，保持不同概念独立，可靠地更新已有笔记，保留人工内容和公式结构，并让重复保存不产生无效更新。
